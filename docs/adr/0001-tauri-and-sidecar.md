# ADR-0001: Tauri 2 desktop shell with a Swift observer sidecar

- Status: accepted
- Date: 2026-07-17
- Deciders: product engineering

## Context

Maman needs an always-on-top transparent pet window, a consent panel, an
encrypted local store, and privileged macOS observation — with a hard trust
boundary between UI code and the code that touches Accessibility APIs, the
Keychain, and local data.

## Decision

- **Tauri 2** hosts both windows. The webview is untrusted relative to the Rust
  core; per-window capability files expose the smallest command set (the pet
  window gets drag + events only — never filesystem, connector, or store surface).
- **Swift sidecar** (`native/macos-observer`) owns AXObserver/NSWorkspace/
  ScreenCaptureKit work, speaking JSON Lines over stdin/stdout, with no network
  entitlement and no networking code (CI greps its dependency graph).
- The pet renderer sits behind a `PetRenderer` interface. Production uses the
  pixel-art `SpritesheetPetRenderer` (original Maman atlas, spriteVersionNumber 2,
  deterministic TS frame scheduler — no CSS keyframes); the SVG renderer remains
  a registered fallback. The atlas is generated by an in-repo script
  (`apps/desktop/scripts/generate-spritesheet.ts`) from one parametrized pose
  model — no external artwork is imported.

## Consequences

- Rust core mediates every privileged operation; a compromised webview can only
  call the narrow command set its window was granted.
- Two processes to supervise: Tauri restarts the observer with a bounded policy
  (3 restarts / 10 minutes, then surface failure).

## Alternatives considered

- Electron: rejected — larger attack surface, no capability system, heavier.
- Swift-only app: rejected — loses the shared TS contracts/engines and the
  cross-platform panel UI; slower iteration.
- Observation inside the Tauri process: rejected — mixes privileged observation
  with UI process lifetime and complicates the no-network guarantee.
