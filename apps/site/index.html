Maman a systems prototype for autonomous workflow discovery

The next enterprise agent should find its own job.

Most agent systems begin after someone names the task. Maman starts earlier: it watches permitted workflow structure, detects repeated work, and proposes the agents an organization did not know to ask for.

Maman turns repeated behavior into autonomous harnesses: bounded, testable agents with triggers, tools, approvals, verification, and audit trails.

The gap

Agent creation is still mostly manual.

Someone has to notice the repetitive work first, and the people doing it are the least likely to see it — repetition reads as competence from the inside. Then a builder has to translate tacit behavior into prompts, tools, triggers, and permissions, and most small cross-app workflows never survive that translation because nobody formally specifies them. Existing automation starts after a job is named.

Maman is about discovering the job first. Enterprises do not just need better agents — they need a system that discovers which agents should exist.

What Maman does

Observe → Detect → Suggest → Create → Shadow → Approve → Run → Verify

  1. Observepermitted workflow structure, locally
  2. Detectrepeated movement and task patterns
  3. Suggestthe highest-value automation, proactively
  4. Createa specialized agent in one click
  5. Shadowrun without writing, first
  6. Approveconsequential actions, bound to an exact proposal
  7. Runthrough local or connected adapters
  8. Verifyby independent readback, and keep receipts

The product is not screen watching for its own sake. It is a compiler from repeated work into governed agent infrastructure.

Autonomous harnesses

The operating contract around an agent.

An autonomous harness is the operating contract around an agent: when it runs, what it can see, what tools it can use, how far it may go, when approval is required, how success is checked, and how it can be paused or revoked.

  • Triggerwhen it wakes
  • Contextwhat it may see
  • Capabilitiesthe tools it holds
  • Permissionsexplicit, per surface
  • Approval policybound to exact diffs
  • Budget & limitsruntime, writes, cost
  • Verificationindependent readback
  • Receiptmeasured, auditable
  • Revocationpause or delete, instantly

The model supplies intelligence. The harness supplies enterprise dependability.

Enterprise interaction surface

Most enterprise work has no API.

Maman is designed to reach beyond APIs by using local adapters, browser control, accessibility, and CLI fallbacks, while keeping permissions explicit and actions bounded.

  • APIs & MCPpreferred, where they exist and are authorized
  • Browser relaysigned local channel into web apps without APIs — origin-enforced
  • OS accessibilitystructured reads of desktop apps
  • Local CLI adapterstyped arguments, never raw shell strings
  • Files & clipboardonly where explicitly permitted, never captured
  • Human approvalfor uncertain or consequential writes, every time

Inspect it

The prototype runs locally, on your Mac.

Download the local build universal · macOS 14+ · release notes & checksums

Install (five steps, about two minutes)

1 · Download and open Maman.dmg.  2 · Drag Maman into Applications.  3 · Right-click → Open the first time — this preview is not notarized, so macOS warns that the developer cannot be verified; the right-click path shows an Open button.  4 · Grant Accessibility and click Always Allow on the keychain prompt (it unlocks the encrypted local database).  5 · Choose what it may watch — nothing is observed until you say so.

If macOS says the app is damaged, clear the quarantine flag: xattr -dr com.apple.quarantine /Applications/Maman.app

What it can see, and what it never collects

Observation records the shape of work: app category, element kind, action type, duration. Labels are hashed before storage. Everything lives in an encrypted database on your Mac with the key in your login keychain; there is no account, and the replayable action-trace layer is local-only by type — it cannot be shaped into a sync payload.

Recorded Not recorded
"a field was committed on an invoice" what you typed into it
"a table was read in a spreadsheet" the contents of the table

Never collected: keystrokes, passwords, payment fields, password-manager content, private browsing. One exception exists to the no-pictures rule: an explicit, user-started Teach Mode session captures the apps you pick, masks credential-shaped regions on device, sends those frames to a vision API to infer workflow steps, and discards them — it is off by default, scoped, and self-terminating. Privacy → Delete data removes any app's history or all of it.

Troubleshooting

The dot is not green. That is the point of the dot — it goes green only when Maman is genuinely observing. Grey or amber means observation is paused or the observer is starting; "Accessibility permission needed" means the switch in System Settings is off; "Needs keychain access" means macOS did not release the database key — quit Maman, open it again, and click Always Allow.

No suggestions yet. Expected early on: a workflow has to recur enough times, on enough separate days, and survive a replay test. Maman shows which bar it has yet to clear rather than leaving you guessing.

Removing it completely: rm -rf /Applications/Maman.app and rm -rf ~/Library/Application\ Support/com.maman.desktop — the second deletes the encrypted database. Privacy → Delete device data does the same from inside the app, including the keychain key.
